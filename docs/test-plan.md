# pledge-checkout-demo — 測項清單

- 單元與整合測試使用 Minitest；畫面流程使用 Rails 系統測試（Capybara ＋ 無頭 Chrome）
- 執行：`bin/rails test`、`bin/rails test:system`
- 標【Demo】的項目可以在 Demo 時現場展示

## C. 建立訂單與驗證

| ID | 情境 | 預期 |
|---|---|---|
| C1 | 選信用卡並完整送出 | 建立 pending_payment 訂單與 payment；導向假金流；名額加 1 |
| C2 | 選 ATM 並完整送出 | 產生虛擬帳號與繳費期限；導向訂單頁 |
| C3 | 繞過畫面限制送出 `aftee` | 422 尚未開放；不建立訂單、不扣名額【Demo】 |
| C4 | 不存在的付款方式 | 422 |
| C5 | 必填欄位缺漏、電話格式錯誤 | 422，保留已填資料 |
| C6 | 手機載具 `/AB1CD23` | 通過；缺 `/` 或長度錯誤 → 422；空白 → 通過 |
| C7 | 公司發票缺統編或抬頭、統編不是 8 碼 | 422 |
| C8 | 同一個 checkout_token 送出兩次 | 只有一張訂單【Demo】 |
| C9 | 下單時折扣碼無效 | 422，不建立訂單 |

## E. Callback

| ID | 情境 | 預期 |
|---|---|---|
| E1 | 簽章正確，success | 訂單轉 paid，回 200 |
| E2 | 簽章正確，failed | 訂單轉 failed，釋放名額 |
| E3 | 簽章錯誤 | 回 401；訂單與名額都不變【Demo】 |
| E4 | 缺少簽章或時間戳 | 回 401 |
| E5 | 內文被竄改、或用錯誤密鑰簽章 | 回 401 |
| E6 | 時間戳超過 5 分鐘 | 拒絕 |
| E7 | 同一個 event_id 收到兩次 | 第 2 次回 200＋duplicate；只轉換一次【Demo】 |
| E8 | 同一個 event_id 由兩條執行緒同時送達 | 只有一個 applied |
| E9 | 已 paid，又收到不同 event_id 的 success | 忽略 |
| E10 | 先收到 failed，再收到 success | 訂單維持 failed；記錄忽略原因 |
| E11 | 先收到 success，再收到 failed | 訂單維持 paid；failed 被忽略並記錄 |
| E12 | trade_no 不存在 | 回 200＋ignored |
| E13 | 金額不符 | 訂單維持 pending_payment；payment 標為 needs_review(amount_mismatch) |
| E14 | E13 之後查看訂單頁 | 顯示「付款資訊異常，客服將與你聯繫」 |
| E15 | 訂單已 expired 或 cancelled 才收到 success | 訂單不變；payment 標為 needs_review(late_payment)；訂單頁顯示將辦理退款 |
| E16 | 內文不是 JSON 或缺少欄位 | 回 400 |
| E17 | 瀏覽器直接造訪 `/orders/:id?status=paid` | 狀態不變【Demo】 |
